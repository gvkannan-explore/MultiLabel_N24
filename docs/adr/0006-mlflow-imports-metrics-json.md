# MLflow is a local view imported from each run's metrics.json

Experiments are tracked with self-hosted MLflow rather than Weights & Biases, because it needs no account and costs nothing. Training never talks to MLflow: the trainer writes its dev metrics, hashes, and `log_history` curves to `metrics.json`, and `src/track/import_run.py` logs that file into a SQLite store on the laptop after the run. A Modal run therefore needs no MLflow server, secret, or database on a Volume, where SQLite file locking is undocumented. The cost is that curves are visible only after a run finishes, not while it trains; during a run, the trainer's log lines stream to the `modal run` terminal. If live charts become necessary, prefer the Weights & Biases free tier (`report_to="wandb"` and a Modal secret) alongside the import, over running an MLflow server on Modal or tunnelling to a local one. `bins/ci_tasks/train_modal.sh` copies each Modal run's `metrics.json` to `metrics/<run>.json` in git, so reviewers see the numbers and any clone can rebuild the store by importing `metrics/*.json`; the store itself is a git-ignored cache.
